# Contributing

Bug reports, documentation improvements, and focused code changes are welcome.

## Before opening a pull request

1. Check existing issues and pull requests for related work.
2. Keep each change focused and explain the user-visible reason for it.
3. For code changes, run the relevant checks when practical:

   ```sh
   pnpm check
   pnpm test:e2e
   ```

4. Describe what changed and how you verified it in the pull request.

For security issues, follow [SECURITY.md](SECURITY.md) and use the private reporting channel instead of a public issue.
